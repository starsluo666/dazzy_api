# 达人多媒体资料与履约提醒

## 业务规则

- 达人资料支持 1–9 个有序素材，其中最多 2 个视频，每个不超过 10 秒。首项必须为照片；每张展示照片统一裁剪为 5:4，列表、轮播及大图预览使用同一裁剪图。
- 图片支持 JPG/PNG/WebP/HEIC/HEIF、8MB 限制；视频支持 MP4/MOV、50MB。新视频校验容器、实际解码并转为通用 H.264/AAC MP4；不做人脸识别。依赖及限制见 [媒体上传兼容部署说明](media-upload-compatibility.md)。
- 增删媒体、调整顺序均随资料修订审核；待审核、驳回不会覆盖已发布资料。首次综合开通审核与后续资料审核都会原子发布完整媒体列表。
- 用户详情支持左右滑动、点击图片预览、手动播放视频；切换素材或离开页面暂停视频。
- 达人接单弹窗要求实名认证本人履约，禁止代接、转单；上传集合照前提示照片必须清晰包含本人及到场环境。后端仍强制先上传履约照才能开始服务。
- 达人“我的”名称旁展示实际评分，无评分时显示“暂无评分”；账号设置展示平台记录的信用分，不做客户端推算。

## 接口兼容

- `PATCH /api/v1/providers/me/profile/` 新增 `media_ids: UUID[]`，顺序即展示顺序。素材必须属于当前用户，且为已上传的公开达人照片或视频。
- 自己的资料、用户端详情、后台审核详情返回 `media: [{id, type, url, duration_ms}]`。`type` 为 `image` 或 `video`；时长由服务端核验，图片及未核验的历史视频为 null。
- 保留 `lifestyle_photo_id/url`，与首张照片同步；旧客户端仅更换生活照时保留其他素材，仅修改文字时保留全量媒体。新提交均要求所有照片完成裁剪，见文末升级说明。
- `POST /api/v1/media/provider-videos/`：已通过达人申请的账号可 multipart 上传，字段 `file`，返回 `{data: {id, url, duration_ms}}`。
- 工作台新增 `rating`、`credit_score`；账号安全新增 `provider_credit_score`（无达人资料为 null）。

## 发布与验收

1. 先部署后端并执行 `uv run --env-file .env python manage.py migrate --settings=config.settings.local --noinput`。新增迁移为 mediafiles 0002、providers 0017/0018；旧生活照自动成为首张图片，历史待审核修订也回填。执行前确认目标环境并按常规流程备份。
2. 网关请求体上限需覆盖 50MB 视频及 multipart 开销（建议至少 60MB），上传超时需覆盖慢网；客户端视频上传超时为 180 秒。确认 COS 视频读取与微信小程序媒体域名配置可用。
3. 同步发布后台、用户端和达人端。当前任务只增加迁移文件，不自动修改业务数据库。
4. 真机验收：一次多选照片、MP4/MOV 上传、调整首图、混排图片与视频、视频播放后滑动/退页停止、审核前后公开内容、拒绝接单弹窗不发请求、缺少履约照无法开始、信用分与后台一致。

自动化覆盖素材归属、数量限制、重复/私有/未上传素材、审核隔离、审核时失效回滚、综合开通发布、旧客户端兼容、视频伪装与截断、真实评分和信用分。

2026-10 新规则增加 `mediafiles.0004_mediaasset_duration_ms` 迁移：视频上传前后均校验时长，资料提交与审批复查数量和时长。既有公开视频不自动下载、删除或转码；历史视频时长为 null，下一次修改资料时需移除并重传，待审资料含旧视频时应驳回请达人重传，不可绕过审核校验。前端 `maxDuration=10` 只辅助录制/选择，服务端 FFprobe 才是最终依据。

## 全部展示照片统一裁剪（2026-10-13）

- 达人端「达人资料 → 添加照片」支持多选并逐张确认取景，拖动移动、滑块缩放，固定 5:4，输出 1000×800 JPEG。确认后才加入相册；取消本轮时，仅保留已确认的照片。每张已有照片也可重新裁剪，第一张直接作为封面，不再维护独立封面/原图两套素材。
- 列表、首页推荐、详情轮播的图片区域同步为 5:4；详情放大预览使用同一裁剪图。视频仍最多 2 个、每个不超过 10 秒，不强制裁剪视频。
- 新照片先通过 `POST /api/v1/media/provider-photos/preview/` 生成方向校正、去元数据的 JPEG 预览。返回 `{data:{preview_base64,width,height}}`，其中尺寸是方向校正后的源图尺寸，预览最长边 1024。接口不创建素材记录、不写 COS，并返回 no-store。微信端预览写入本次专用临时文件，关闭裁剪时清理该预览；不删除用户手机原照片。
- `POST /api/v1/media/provider-photos/crop/` 接收归一化 `x,y,width,height` 并返回 `{data:{id,url,cropped:true}}`。预览与裁剪接口均支持：新照片 multipart 的 `file`；或已有照片 JSON 的 `source_id`，两者不可同时传。新照片的原始字节仅用于请求内解码，只有最终裁剪 JPEG 入库和写入 COS；已有线上照片不覆盖、不批量删除，以保留审核隔离。
- 两个接口复用同一方向/HEIF 解码逻辑，校验实际格式、8MB/2500万像素、素材所属用户和公开已上传状态；裁剪额外校验边界、最小取景尺寸和 5:4 比例。只按可信 COS key 读取旧照片，不接受任意 URL；预览与裁剪合计每用户每分钟最多 30 次。
- 相册返回 `media[].cropped`。资料提交仍使用 `media_ids`，`lifestyle_photo_id/url` 始终与首图同步；不增加单独的 cover_photo_id。服务器要求每一张图片都已裁剪，审批也复查。前端、旧客户端或绕过前端提交未裁剪照片都会被拒绝。
- 裁剪只是编辑草稿素材，提交资料审核通过后才替换当前发布资料。旧线上照片不会自动裁剪、下架或删除；下次提交资料时需全部完成裁剪。升级前已有待审资料如含未裁剪照片，客服需驳回并说明逐张裁剪后重提，不可直接通过。
- 发布顺序：先执行新增迁移 `mediafiles.0005_mediaasset_provider_photo_cropped` 并部署后端，再发布达人端和用户端。历史标记默认为 false，不擅自认定旧图符合比例；无新增运行依赖。原上传接口仍供入驻意向等旧流程使用，但不能代替正式达人资料的裁剪校验。
- 自动化覆盖新照片预览不持久化、最终仅保存裁剪图、HEIF/EXIF、归属校验、无效参数/格式、频率限制、每张照片强校验、审核隔离及失效回滚；H5 覆盖 320/390/430px 的多选队列、拖动缩放、取消/重试、重排及同图放大。部署后需用微信真机验证苹果照片、多图选择、临时预览清理以及审核发布。
