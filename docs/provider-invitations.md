# 达人邀请：第一阶段上线说明

## 门店工作台与首单奖励

- 后台「营销管理 → 达人邀请 → 邀请来源」可绑定收款负责人真实姓名、手机号。负责人用短信验证码登录达人端，进入门店工作台。门店账号完成身份证验真与客服审核后，以负责人本人开通汇付个人用户、绑定本人银行卡并申请提现。
- 「奖励规则」分别配置门店与达人。注册奖励使用固定金额，首单使用固定金额或净服务费比例。规则在邀请注册时留存。历史邀请归属通过迁移补齐，新规则从新注册生效；已有人工奖励按原流水核对和登记。
- 首笔正常确认、已支付、冻结期结束且无退款或未结售后的服务订单生成一笔首单奖励。订单处于待评价也可计奖。奖励比例以优惠后的净服务费为基数，金额四舍五入到分。
- 新奖励由具备审核和付款权限的财务人员确认。Celery 任务在本地登记唯一流水和资金占用后发起汇付余额支付，只按原流水查单。查单核实到账后记入收款人可提现余额，渠道结果列于奖励台账并纳入渠道对账。出现已验签的渠道证据冲突时，台账进入「待人工核账」并保留资金占用，后续自动查单不能代替人工核账。
- 首次上线执行数据库迁移并更新 API、Worker、Beat、运营后台和达人端。通过与汇付确认的出款基本户提供平台自有资金，确认业务用途、风控 IP、限额及费用模式后设置 `HUIFU_INVITE_REWARD_PAYOUT_*`（见 `.env.example`）。`FEE_MODE` 取已核验的 `merchant_payer` 或 `request_payer`，费用预留和单笔限额均用分。资金不确定时先核原流水；关闭新出款开关后，已登记流水仍由任务查询。

下文记录既有人工发放规则和首期配置。

## 业务口径

- 门店、已通过入驻初审的达人可邀请新手机号账号；共用**用户端 H5** `pages/invitations/provider-register`（免登录）。首页、菜单、常规注册及“成为达人”不增加此页入口，只通过带有效邀请码的二维码/链接进入；无效、缺失、停用邀请码不可注册。网页不能可靠区分扫码和复制链接访问，不用 Referer 或客户端参数充当安全校验。
- 注册后在用户端 `pages/invitations/application` 查看入驻初审进度（须登录），通过后提示使用同一手机号和密码登录达人端完善接单资料，不跳转用户端不存在的工作台。用户端和达人端登录态各自保存，不通过 URL 传递令牌。达人端保留申请进度页：未通过初审的账号登录或打开工作台时进入进度页，初审通过后进入工作台。审核被驳回显示原因，需联系平台核对；不重复注册或重新绑定邀请人。
- 手机号短信校验、密码、真实姓名、出生日期（18～100岁）、男/女性别、近期生活照、已开放服务城市、协议同意一次提交。
- **注册且完整入驻意向提交成功**产生一笔待财务审核奖励，不要求先接单，也不把“入驻初审通过”冒充注册成功。入驻审核与奖励审核是两个不同流程。
- 金额单位为分，门店与达人金额分别配置；注册时锁定金额、规则版本、邀请来源名称和代码。之后调价、停用来源不修改历史奖励。
- 同一新账号只记录一次；已有手机号不能通过此入口重复注册/绑定。邀请来源不能在被驳回后修改。普通用户邀请送券不叠加触发。
- 奖励独立台账，不进入用户钱包、达人订单收入、汇付分账/提现；本功能无任何真实打款调用。

## 部署与配置

达人招募邀请码统一为 4 位大写字母与数字，例如 `A7K9`，随机生成时避开 `0/O`、`1/I`。
新建来源遇到随机码冲突会在数据库唯一约束下重新分配；不同来源不会共用邀请码。
`growth.0003_four_character_provider_invite_codes` 将现有长码换为四位码，并保留原码用于识别旧二维码及链接。
原邀请来源 ID、邀请归属和奖励快照保持不变，停用来源后新旧链接均不可注册。
上线需同步更新 API 和用户端 H5（以及仍保留的达人端邀请注册兼容页），避免旧页面拒绝四位码。
普通用户邀请领券使用的 UUID 邀请码不受本次调整影响。

1. 更新 API 依赖并执行迁移（含 growth/0002、backoffice/0038），默认关闭活动、奖励金额为0。
2. 构建并部署 **dazzy_app 用户端 H5**、管理后台；达人端仅保留邀请分享和进度功能。二维码是普通 HTTPS 二维码，不是微信小程序码；不能只发布达人小程序或后端而不更新用户端 H5。用户端正常“成为达人”流程保持不变。
3. 后端 `.env.online` 中 `PROVIDER_INVITE_H5_BASE_URL` 必须显式填写实际**用户端 HTTPS H5 根地址**，例如 `https://h5.ledaban.cn`（不带 `#`、查询参数、用户名密码）。保留环境变量名以兼容现有配置；它只影响链接生成，不会部署前端。没有默认域名，缺失或格式无效时不允许启用邀请/注册或生成二维码，已有奖励台账仍可查询和审核。已指向 `h5.ledaban.cn` 的二维码在更新该域名用户端 H5 后可继续使用；若之前填了其他域名，须改为用户端地址、重新部署后端并下载二维码。生成邀请链接不依赖请求 Host。跨域部署时还需配置 API 的 CORS 允许来源；也可用同域 `/api/v1` 反向代理。
4. 后台「营销管理 → 达人邀请 → 奖励规则」分别设置门店/达人奖励后开启。
5. 「邀请来源 / 门店二维码」创建门店，下载二维码；真实印刷前扫码确认邀请人、链接、开放城市和上传均正常。
6. 达人端「我的 → 邀请达人」自动获得专属稳定邀请码，可以复制链接或分享二维码，查看本人脱敏邀请记录及待审核/待打款/已打款金额。

### 权限

- `provider_invite.view`：查看全平台来源及奖励台账。
- `provider_invite.manage`：配置奖励、创建门店、启停邀请来源。
- `provider_invite.review`：审核奖励通过/不通过。
- `provider_invite.pay`：登记实际人工打款结果。
- 后三项均须同时有查看权限，且组织必须为平台、数据范围为全部。区域/城市账号不能访问，即使错误授予 `*` 也不放行。
- 迁移仅为既有 `platform-admin` 全平台系统角色增加权限，不扩展普通客服或财务角色。其他角色在「账号与权限」按岗位单独授权。

## 财务操作

1. 待财务审核：核验真实新注册、意向资料、归属、金额及异常/重复身份风险，填写审核说明，通过后进入待人工打款。不符合要求则驳回并留原因。
2. 待人工打款：财务在线下核验门店合作主体/达人本人收款资料。**先查历史记录与银行流水、落实唯一经办人，再线下转账**。
3. 转账完成后「登记已打款」，填唯一转账流水号、实际打款时间、收款人核验说明，并明确勾选已完成线下转账。不要在备注中填写完整身份证/银行卡号。
4. 第一阶段一笔奖励对应一笔转账，不支持合并转账或拆分付款。流水号全局唯一；并发/重复登记只允许一笔状态迁移。已审核/已支付记录不允许覆盖重写。
5. **系统防重只作用于台账，不可能阻止两名人员在外部银行重复转账**；人工付款必须遵循单人经办、流水核对流程。第一阶段不自动核验银行到账，也不支持自动追回已打款奖励。

## 故障与安全边界

- 注册事务失败时账号、申请、奖励一起回滚；已上传成功的生活照尽力清理，清理失败记录日志供存储核查。
- SMS 验证码属于一次性缓存凭证，数据库回滚不会恢复它。上传失败后如验证码已失效须重新获取；请求超时但服务端可能已提交，提示“已注册”时用该手机号登录查看入驻申请，不能重新计奖。
- 身份真实性仍须平台初审、后续实名和财务核验；短信注册只能证明手机号控制权，不保证一人只持有一个手机号。不要无人审核直接付款。
- 邀请人的未审核/未打款奖励会阻止账号注销；停用接单资格后仍可查看已有奖励，但不能继续产生新邀请。
- 部署前备份；本次未运行生产迁移，未发送真实短信、未上传真实照片、未转账。
