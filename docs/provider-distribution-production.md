# 达人分账正式资格模式（2026-10-15）

## 本次改变

现有 Django / Python `dg-sdk==2.0.24` 聚合支付链路取消逐个登记达人 ID 的试点限制。
新延时支付、手动分账、自动分账、收入页提现资格和达人主动提现，均不再读取
`HUIFU_PROVIDER_DISTRIBUTION_IDS`。该旧配置应从服务器环境文件删除；即使残留也不生效，
空值、旧数字列表或 `*` 均不会限制正式模式的参与范围。没有新增一套试点/正式切换开关。

正式模式指**按真实业务与账户资格决定是否参与**，不代表所有人无条件出款，也不表示已完成真实资金验收：

- 审核通过、实名认证通过，收款用户和当前授权有效，本人提现卡、手动提现能力、
  自动结算关闭状态及平台承担提现费用必须按原规则核验。沿用现有自动结算缺失字段处理规则，
  不新增对渠道响应的假设。
- 新支付仍须开启延时支付开关、确认平台手续费规则、配置正数单笔限额。
  收款资格未满足时拒绝该次全额外部支付，不静默降级成无法自动分账的普通支付。
  账户查询过期仍复用现有事务外刷新和一次重检，不改变已登记支付的原流水恢复逻辑。
- 分账仍要求原支付为 `Y` 且不可变范围快照完整；订单已确认完成、冻结期结束、
  平台账务已结算、无待处理履约异常/售后/退款，并完成原支付、资金、接收方及费用核验。
- 仅查询核验成功后计入达人收入余额；同步受理不等于入账。自动任务不会替达人申请提现。
- 提现仍须独立开启、满足提现限额、可用余额和无冻结条件；执行前重新查询本人卡、
  手动提现配置和渠道余额，在事务内预留余额，登记唯一流水后才请求渠道。
- 原请求、通知处理、SDK 签名验签、终态确认、幂等、防重复出款与异常只查原流水机制不变。

## 仍未扩大支持范围

旧的 `delay_acct_flag=N` 支付、没有原始分账范围快照的支付、历史待人工核账结算，
不会因升级正式模式而补分。不允许改成 `Y` 或伪造快照。
原有有效 `Y` 支付保留其快照和请求身份，可以继续按原流程核验。

余额/混合支付、活动订单及充值不新增本链路的分账支持；已成功部分退款的订单、
取消/提前终止/履约售后剩余款仍按原规则转人工核账。已登记分账后的自动回退、
退款重分、提现后的资金追回和账单级持续对账等未因取消白名单而自动实现。

## 部署与启用

本次无数据库迁移，不修改真实环境文件，不自动开启任何资金开关，不调整实际费率或限额。
Docker 默认业务配置文件为服务器项目内 `.env.online`；若 `.env.docker` 中
`DAZZY_ENV_FILE` 指定其他路径，以实际路径为准。

**若旧部署已开启资金执行，升级后原白名单不会继续限制参与者。**
发布前应在维护窗口将新增延时支付、分账执行、提现执行和收入任务开关关闭并应用到旧进程，
再同步发布 API、Worker、Beat，核对配置与符合条件的存量 `Y` 支付，最后显式授权启用。
不要只更新 API 或假定残留的旧名单仍能隔离资金范围。关闭开关不会撤销已在途的资金请求；
保留原流水查询和人工核账。

配置项仍默认安全关闭：

```dotenv
HUIFU_PROVIDER_DELAYED_PAYMENT_ENABLED=false
HUIFU_PROVIDER_DISTRIBUTION_ENABLED=false
HUIFU_PROVIDER_INCOME_JOBS_ENABLED=false
HUIFU_PROVIDER_PLATFORM_FEE_POLICY_CONFIRMED=false
HUIFU_PROVIDER_DISTRIBUTION_MAX_CENTS=0
HUIFU_PROVIDER_WITHDRAWAL_ENABLED=false
HUIFU_PROVIDER_WITHDRAWAL_MAX_CENTS=0
```

手续费规则由渠道人工确认后才能将确认项设为 `true`，这不会修改渠道实际费用配置。
分账限额单位是分，包含服务、交通等订单支付金额，**不是仅限制达人的份额**；
开启新延时支付后超限会拦截该次支付，不静默转普通支付。提现限额是另一独立配置。
`HUIFU_FEE_FLAG` 继续按已确认渠道配置使用，旧单仍以首次支付快照为准。

建议在内部注册范围内先验证一笔新全额外部支付：刷新合格达人的收款账户 → 新支付为 `Y`
且范围快照完整 → 完成订单 → 等待冻结期 → 分账核验成功 → 收入余额 → 主动提现 → 核对银行到账。
正式资格模式不会替代注册权限控制，也不会替代真实小额验收。

仅修改配置时，现有发布脚本 `sudo bash ./deploy-docker.sh start` 使用当前镜像重新应用
API/Worker/Beat 配置；部署本次代码仍须发布新镜像。不要只用容器 `restart` 期待环境更新。
核查旧订单不能沿用旧的白名单检查表达式：配置读取已删除，不再有该 Django setting。
