# 腾讯云身份证人像照片验真

对接 `faceid.tencentcloudapi.com / CheckIdCardInformation / 2018-03-01`。
参考：[官方接口文档](https://cloud.tencent.com/document/product/1007/47276)。

## 业务边界

- 新版达人端选择身份证人像面后先上传并自动保存，再经明确授权调用独立验真接口，回填姓名和脱敏证件号；取消授权保留已保存照片，允许主动重试。页面不再提供“保存资料”按钮。仅上传/保存接口、刷新页面、客服查看均不调用腾讯；新版上传人像面的完整交互会在授权后发起付费验真。
- 新版达人端只上传三张照片：身份证人像面、国徽面、本人自拍，不再手填姓名和证件号。保存/提交请求带 `recognition_mode=photo`，不会回退到旧版手填人工流程。
- 已上传的身份证人像面与权威库比对；要求 `Result=Success`、相似度至少 70、无告警，OCR 姓名必须与入驻申请一致，返回证件号必须完整有效。通过后将识别姓名、证件号摘要和脱敏号码写入现有实名字段，供收款资料核对继续使用；只读展示，不接受客户端手动修改。
- 验真通过后只回填信息，不进入人工审核、不锁定整套资料。补齐国徽面和自拍后点击“提交认证”才进入人工审核；此步骤仅校验已存在的凭据，不再调用腾讯，也不会自动实名认证成功或开通达人。国徽面有效期、本人自拍仍需客服人工审核；只把人像面提交腾讯接口，不发送国徽面或自拍，不接活体检测，也不做自动自拍比对。
- 客服在“达人详情”和“达人开通审核”查看结果、相似度及腾讯 RequestId；两种审核入口均检查当前材料的验真凭据，不能复用已变更材料的结果。
- 历史已认证或已经进入人工审核的资料不自动付费补验、不自动失效；历史人工认证明确展示“未验真”，不伪装腾讯验真成功。

## 部署与启用

1. 先部署后端并执行迁移至 `providers.0025_provideridentitycheck_material_scope`（包含前置 `0024_tencent_identity_verification`），再发布新版达人端。新增 `material_scope` 区分旧整套材料凭据与新人像面凭据，历史记录默认 `all`，不会自动付费补验。
2. 在腾讯云开通本接口对应服务及计费权限。推荐专用 CAM 子账号，最小权限为 `faceid:CheckIdCardInformation`，以腾讯控制台实际授权为准。
3. 配置 **后端** `.env.online`（不是小程序 `.env`，不是 `.env.docker`）：

```dotenv
TENCENT_FACEID_ENABLED=false
TENCENT_FACEID_SECRET_ID=
TENCENT_FACEID_SECRET_KEY=
TENCENT_FACEID_TIMEOUT_SECONDS=12
TENCENT_FACEID_DAILY_LIMIT=5
```

两项专用密钥均为空时沿用后端现有 `TENCENT_CLOUD_SECRET_ID/KEY`；仅填一项视为配置不完整，不混用专用/共享密钥。COS 读取继续使用原 COS 凭证，不要求 FaceID 专用凭证具备 COS 权限。

4. 先在测试环境设置 `TENCENT_FACEID_ENABLED=true` 并重新部署加载环境，经用户授权，用本人真实证件完成水印识别、权限及异常联调，再在生产启用。开关是全局开关，不是白名单开关；不要把密钥发到聊天、提交 Git 或写到前端。
5. 开关关闭时不允许新发起验真，照片仍可自动保存；没有有效凭据不能提交审核绕过验真。已有当前材料的有效凭据可以继续提交人工审核，此动作不调用腾讯。历史已提交/已认证资料不失效。仅旧客户端未进入照片识别流程、且开关关闭时继续兼容原来的手填人工流程。

## 新旧客户端接口

- `PATCH /api/v1/providers/me/identity/`：照片上传成功后自动保存对应的一个 `identity_*_photo_id`，并传 `recognition_mode=photo`；不覆盖另外两张照片。
- `POST /api/v1/providers/me/identity/verify/`：传当前已保存的 `identity_front_photo_id` 和 `consent_version`；后端核对照片未变化、归属/私有存储/状态与授权。只需要人像面，成功后仍为未认证/待修改状态。
- `POST /api/v1/providers/me/identity/submit/`：新版明确传 `recognition_mode=photo`、`verification_mode=preverified`；严格检查三张材料和当前有效凭据，只进入人工审核，不在凭据缺失/过期时偷偷补验。旧版未传 `verification_mode` 时保留原有“授权验真后提交”行为。
- 新版将姓名与脱敏身份证号放在照片区下方只读展示，初始提示“请上传身份证照片”。不再展示独立验真提示卡片或重试按钮；异常仍即时提示，取消授权或识别失败后可重新上传人像面触发验真，重进页面或刷新不自动付费重试。

## 照片、隐私与水印

- 后端从自己配置的 COS 私有桶读取当前用户所属、已上传的认证材料，不接受任意 URL。原有“仅用于达人验证”水印继续保留，不另存无水印原图。
- 历史 WebP 等图片在内存转为 JPEG，去除 EXIF/GPS，最大边长 3000，Base64 不超过 7 MiB；读取上限 8 MiB、2500 万像素上限，适配现有 HEIC 转码上传链路。
- 开启 `Quality` 告警。平台水印可能触发 PS/遮挡规则，因此不额外开启这些可选告警；不代表关闭接口本身的人像和证件真伪核验。必须实测水印是否影响 OCR/人像识别；若影响需另行设计经授权的原图验真流程，不能静默移除水印。
- 验真记录仅持久化材料指纹、授权版本/时间（记录创建时间）、状态、固定安全文案、结果码、相似度、RequestId。成功时自动更新达人实名姓名、证件号 HMAC 摘要与脱敏号码；姓名受现有私有接口和审核权限保护。不保存腾讯响应中的明文证件号、住址、民族、生日、证件抠图或完整响应。
- 新验真凭据绑定人像面：更换人像面会清空识别字段并使旧凭据失效；补传/更换国徽面或自拍只更新待审核材料，不重复调用腾讯。旧整套凭据保留原有绑定规则，更换任一材料仍会失效。最终提交和客服通过时仍检查所有照片的归属、私有属性及有效状态。失败、超时或过期返回不能写入新的实名信息。返回结果的数据对象也隐藏实名字段的日志表示。
- 禁止腾讯 SDK 请求/响应日志，避免图片 Base64、证件号及密钥进入 DEBUG 日志；异常不回显第三方原文。达人认证接口响应为 `no-store, private`。

## 重复提交与异常

- 使用数据库行锁分配尝试，远端调用不持有数据库锁。验真期间拒绝修改或重复提交；返回后重新核对材料指纹、账户状态及尝试编号。
- 每达人每 24 小时最多 5 次（可配置），两次尝试间隔至少 30 秒；无 SDK 自动重试。网络超时也可能已经计费，不承诺超时免费。
- 进程异常等导致验真未完成，2 分钟后可先刷新状态，再由达人明确重新验真；旧结果不能覆盖新尝试。最近 24 小时内符合凭据绑定范围的成功结果可复用，未提交/已驳回资料超过 24 小时需要重新验真。已进入人工审核或已通过审核不因等待超过 24 小时而自动失效。
- 低相似度、识别姓名与入驻姓名不符、图片告警返回可读失败原因；欠费、未开通、签名异常、超时或无效响应均阻止提交，不降级放行。客服可通过 RequestId 向腾讯排查。姓名不符应先核对证件，再由客服更正入驻申请，不允许在实名认证页面覆盖识别姓名。

- 达人端 `node --test tests/identityVerification.test.cjs tests/identityUpload.test.cjs`；类型检查、微信小程序与 H5 构建。
- 达人端 H5 构建后可运行 `node tests/identityVerification.browser.cjs`（需 Playwright / Chrome），使用合成照片和本地 API 模拟，覆盖自动保存、首次授权、取消后重试、回填、背面/自拍不重复验真及最终提交；不上传真实证件。
