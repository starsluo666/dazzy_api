# 资金上线检查

入口：财务管理 → 资金处置与巡检 → 资金上线检查。
API：`GET /api/v1/admin/payment-readiness/`，要求已有 `finance.recovery.view`
权限及全平台数据范围；城市或组织范围的角色不能读取。沿用既有菜单与权限，无新迁移。

页面检查当前 API 进程的五组配置：微信收款、达人延时分账、余额／组合支付的达人结算、
达人主动提现、每日渠道对账。分别显示“本地配置齐全”“待补配置”“未启用”；
没有全局“可上线”或“资金验收通过”结论。关闭的功能保留检查明细，不能据此认定应当开启。

检查包括独立业务开关与查询任务开关、正式出款 SDK 配置、密钥本地格式、限额、
余额付款策略与带时区启用时刻、对账起始日期和下载主机格式。纯本地配置校验使用
不可变配置副本独立检查格式，不修改运行中的开关，也不参与任何资金授权。
功能开关与 SDK 参数校验通过仍不能证明商户权限、费用或真实资金结果。

同时复用 `financeops.watchdog.health` 展示异常任务数量并跳转已有巡检。
这反映持久化执行记录，不表示每笔渠道流水均成功，也不能证明 API、worker、beat
当前使用同一镜像或同一份环境配置。部署时仍需核对三个服务。

本接口只读配置与已有任务/账单记录，无网络请求、数据库写入、资金查询或交易操作；
不展示密钥、商户标识、收款账户、通知地址或风控 IP 值。响应设置 `Cache-Control: no-store`。
刷新失败后前端清除旧检查报告，避免继续显示过期的配置通过结果。预览模式不请求实际配置。

汇付能力与账户范围、实际手续费和资金用途、真实小额支付到银行卡到账、通知与故障恢复
作为人工验收项目展示。本页不记录这些项目已完成；已有的确认开关只说明服务端已登记确认，
不替代渠道或银行凭证。分账后的自动退款及历史订单补付规则不在本次范围内。

本次为现有 Django/Python、`dg-sdk==2.0.24` 聚合支付系统的只读上线辅助功能。
使用 `huifu-pay-integration` 的 `copilot-existing-system.md`、`copilot-go-live-checklist.md`、
`copilot-troubleshooting-playbooks.md` 三份 reference 核对存量集成、上线与状态展示口径。
未引入新支付 wire 字段、通知协议或 SDK 调用；既有验签、查单、幂等和终态保护沿用原实现。
