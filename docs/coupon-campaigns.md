# 首页领券活动

后台入口：运营配置 → 领券活动。此功能不等于同城活动，也不自动向全员发券。

## 部署与权限

- 后端部署必须执行迁移 `orders.0037` 和 `backoffice.0039_grant_coupon_campaign_permissions`，同步发布后台和用户端；不需要定时任务。
- 超级管理员可直接使用。`backoffice.0039` 仅为平台组织、全部数据范围的内置 `platform-admin` 角色补齐 `coupon_campaign.view`、`coupon_campaign.manage`，保留其他权限；新建平台管理员时也包含这两项。不会给自定义角色、普通客服或城市/区域角色自动扩权。
- 客服/运营自定义角色须由管理员按需授予以上权限，且必须是平台组织、全部数据范围。只有查看权限时能查看活动与记录，不能配置或发布。
- 平台管理员看不到「运营配置 → 领券活动」时，更新后端并运行 `sudo bash ./deploy-docker.sh deploy --migrate`；迁移成功后刷新后台页面（必要时重新登录）。仅拉代码或只更新前端不会补齐数据库内已有角色的权限。迁移不创建/上架活动、不发券，也不触发短信或资金操作；回滚迁移不撤销既有授权。
- 选图需要 `asset.view`；直接上传需要 `asset.manage`。已有优惠券模板在营销管理中维护。
- 不迁移或创建示例活动、示例券、真实领取记录；不调用短信、微信或资金渠道。

## 配置流程

1. 在素材库上传“图片”（不是图标），推荐 1080 × 616，左下角预留领取按钮空间。
2. 新建领券活动：名称、图片、券模板、领取起止时间、库存、排序。
3. 保存草稿后检查预览，再确认上架。数字越小越靠前，相同排序时后创建的优先。
4. 首页展示最多 20 场当前可领活动，左右手动滑动；无活动时保留原首页主图。不自动轮播、不自动弹窗。
5. 用户点击图片或图上按钮后查看券规则，登录并主动领取。领取成功进入现有“我的优惠券”，发送一条站内发券通知。

## 规则与安全边界

- 每个用户每场活动终身限领一次；券过期、使用、撤销或退款释放都不恢复活动领取次数。不同活动可以分别领取。
- 首次上架锁定券名称、面额、门槛、有效天数和说明。之后修改/停用券模板不会改变该活动；停止新领取须下架活动。换券须新建活动。
- 已发布活动可以改图、名称、领取时间、排序和增加库存；库存不得低于已领取数。客服修改采用版本号防止互相覆盖。
- 下架/到期/领完停止新领取，已领取券仍按领取时的金额、门槛、到期日使用。活动结束时间不等于已领券到期时间。
- 券沿用既有达人订单规则：订单原价**大于**门槛（不是大于等于），每单限一张。不改变余额折扣、路费、退款、分账计算。
- 库存、券、领取记录、通知在同一事务中提交；活动行锁、唯一领取约束、库存检查约束共同防重和防超发。请求超时重试返回原券。
- 图片必须是公开运营图片；引用中的素材不能放入回收站，私有认证材料、用户照片和视频不能用于活动。
- 公共响应不含库存预算、后台操作人或其他用户信息；领取记录仅后台授权人员可见，手机号脱敏。个性化响应禁止共享缓存。
