# 汇付支付异常恢复（2026-09-28）

覆盖活动发布、活动报名、达人订单和余额充值。沿用 V4 聚合支付及锁定的官方 Python SDK `dg-sdk==2.0.24`，没有更换网关、签名、通知验签或入账机制。

## 修复内容

- 同一支付请求只创建一次；出现 `20000000` 重复交易、网络结果不确定、历史失败或提交超时，改用原 `req_date` / `req_seq_id` 查单，不再重复调用创建接口。
- 仍在提交的请求保留 30 秒保护；超过保护时间也只查单，不意味着可以重新扣款。
- 成功或失败响应落库都校验流水、提交次数与提交状态，迟到的响应不能覆盖已经就绪的会话。
- 查单继续校验商户、金额、流水及交易类型；只有服务端查单成功后，才调用原有幂等支付成功/充值入账流程。
- 不返回空支付参数；同步下单返回成功状态也必须查单确认，不凭同步响应或客户端回调入账。
- 新增错误描述脱敏日志，不记录支付参数、签名、密钥或付款人身份；数据库保留现有错误码和摘要字段，没有新增迁移。

## 恢复结果

| 查询结果 | 行为 |
| --- | --- |
| 成功 `S` | 按原流程完成支付/晚到退款处理，返回 `409 huifu_payment_status_updated`；前端刷新服务端状态，不再次唤起支付 |
| 待支付 `P` 且本地有未过期参数 | 复用原会话，不创建新流水 |
| 待支付 `P` 但参数丢失、初始化 `I`、查单失败或暂未查到 | 返回 `409 huifu_payment_pending_confirmation`，明确提示核对中，不自动重付 |
| 失败 `F` | 返回 `409 huifu_payment_closed`；充值关闭原单，其他业务由原取消流程结束旧单后重新下单 |

查询接口不承诺返回 `pay_info`。对于旧版本已经丢失调起参数的订单，本次修复不会伪造参数、清空流水或自动换流水。需等原交易核对结束，或通过已有取消/超时补偿流程确认关单后再创建新单。查询尚未确认不等同于未扣款。

## 发布与排查

需要同时更新 API 和用户端 H5；本次没有业务数据库迁移。API 可按现有部署流程执行 `bash ./deploy-docker.sh deploy`，H5 按项目部署脚本发布。本文不表示已在线上执行。

新增诊断可在 API 容器日志中按 `Huifu create failed:` / `Huifu recovery-query failed:` 检索，日志包含模型名、记录 ID、尝试次数、错误码、脱敏描述和摘要。历史摘要无法还原原始响应，旧记录仍应使用保存的请求日期和流水号查单。

微信弹窗“当前页面的 URL 未注册”属于支付授权目录配置，代码恢复逻辑不能替代商户侧配置。应单独核对正在使用的微信支付商户/服务号对应配置。
