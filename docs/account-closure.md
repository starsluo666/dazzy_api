# 账号注销：5 个工作日等待期

## 生命周期

- `POST /api/v1/auth/account/close/` 验证当前密码，沿用未结余额、订单、退款、结算、活动、投诉的拦截。提交成功只创建申请，不表示已经注销。
- 返回 `closed: false`、`status: pending`、`requested_at`、`execute_after` 和 `working_days: 5`。
- 用户进入 `closure_pending` / `is_active=False`；所有设备的旧 access / refresh、Django session 和新的收费业务都不可用。不清空余额、不删除交易记录。
- 等待期届满前，密码 / 短信 / 微信 H5 / 原生 App / 小程序的身份验证成功，才会撤销申请并发出新会话。失败登录、发验证码、改密码、刷新 token 不会撤销。后台管理登录也不能绕过注销等待期。
- 到期后登录不可撤销，即使后台任务暂未执行。Celery Beat 每 60 秒派发 `accounts.process_due_account_closures`，Worker 到期重新检查未结业务，无阻碍才设为 `closed`；新余额或待处理投诉会使申请进入 `blocked`，待事项妥善处理后重试。不要用直接修改状态或清零余额代替真实结算。
- 申请 / 撤销 / 完成与登录签发使用同一用户行锁；重复请求不延期、重复任务不重复完成。每批 200 个，最近检查时间排序防止暂停事项饿死其他申请，异常可重试。
- `AccountClosureRequest` 留存申请、到期、撤销 / 完成时间和暂停业务；Django Admin 只读可查，不允许直接修改或删除申请。

## 工作日历

北京时间，提交当日不计入；累计后续 5 个工作日，到期时刻与提交的本地时刻一致。包含周末调休，排除国家法定休假。

内置 2026 年日历来自国办发明电〔2025〕7号：
https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html

例如 2026-09-29 14:20 申请，2026-10-12 14:20 到期。已计算国庆休假和 10-10 调休上班。

每年公告后必须维护下一年日历。环境变量 `ACCOUNT_CLOSURE_CALENDAR_JSON` 可扩展年份或完整覆盖某一年的内置日历，结构为：

```json
{"YYYY":{"holidays":["YYYY-MM-DD"],"working_weekends":["YYYY-MM-DD"]}}
```

这是结构说明，不可直接复制为真实日期。两个数组必须完整、日期属于对应年份、不冲突。尚未配置的跨年申请会返回错误并保持原账号可用，不猜测节假日。已有申请保存的到期时间不会被随后日历修改悄悄改变。

## 发布

1. 备份业务库，正常执行 `accounts` 新迁移（新增申请表及用户状态选项，无旧账号重激活）。
2. 协调 API、用户端、达人端和管理后台更新：两个客户端显示等待期与预计时间，后台用户筛选 / 状态包含“注销处理中”。
3. 重启 API、Worker、Beat；确认定时任务注册且仅有一个 Beat。停机后重启可补处理已到期申请。
4. 在测试账号验证到期、等待期登录撤销、未结业务阻拦；不要用真实有余额用户试注销。

## 尚未扩大的范围

原有软注销策略仍保留：最终停用账号及会话，没有在本轮实施用户数据物理删除 / 匿名化、释放手机号 / 微信身份用于重注册。不得把原 DOCX 的相关承诺视为这些功能已经实现；应在上线前由运营 / 法务确认并与实际保留、清理政策一致。
