# 已结算 / 已进入渠道分账订单的人工售后

本期只提供人工工单、金额占用、凭证登记及独立复核。**不调用退款或分账退回接口，不转账，不扣达人收入余额，不把人工结案写成渠道退款成功。** 余额 / 组合支付的渠道结算不在本期范围。

## 发布与入口

- 先部署 API 并执行迁移 `backoffice.0041_provider_manual_refund_case`，再发布后台和用户端。
- 无新增汇付配置项，不需要为此打开任何付款开关。
- 后台：订单管理 → 已结算订单人工售后。原订单详情“登记退款”对符合条件的订单会切换为“转人工售后”。
- 用户端：在线退款不可用时显示“联系售后客服”，仍可查看原售后记录；客服工单不会自动创建财务人工退款工单。
- 运营实时待办和站内工作通知投影增加“已结算订单人工售后”“人工退款凭证待复核”。不发送短信或微信推送。

## 权限与处理

1. 客服凭 `order.after_sales.view` + `order.after_sales.create` 登记金额和核实原因，只能处理其城市范围内订单。
2. 财务凭售后查看 + `order.finance.view` + `order.finance.manage` 开始处理。先核对原支付、已有退款、渠道分账是否终态、达人是否已提现、责任归属和实际可追回资金。原分账处理中、未知或证据冲突时不得标记资金处理完成。
3. **实际退款必须由财务在受控的外部流程执行**。先确认收款人、币种金额、已有汇款流水及承担方，取得与申请金额一致的退款回单后，登记实际退款流水号、内部凭证编号 / 存放位置、退款时间与处理依据。页面不存储收款账号密码或渠道密钥，也不自动核验回单。
4. 另一名具备上述财务权限和 `refund.supervise` 的人员核验并结案。申请人、曾经登记过本单凭证的人员均不能复核，工单退回后换人补充凭证也不解除该限制。复核包括实际到账、是否重复退款、达人已得款的追偿或平台承担，以及原渠道账务和本地收入账务的差异；无法核清则退回补充，不能结案。
5. 尚未发生退款时主管可驳回并释放申请占用。一旦登记过退款流水，退回仍占金额、不得驳回释放或更换流水号。录错流水需先线下核账，目前没有自助撤销或修改终态入口。

## 安全边界

- 相同请求键重放返回同一工单；同订单同时最多一个未结束人工工单。
- 可登记上限 = 原实付款 − 所有已有系统退款金额（含待核实 / 失败占用）− 已核验人工金额 − 未结束人工金额。未完成的原售后或自动退款必须先核查，不能并行登记。
- 退款流水号全局唯一；复核退回后不可替换以释放旧流水。分多次付款或合并付款的复杂退款先由财务核对，目前一个工单只登记一笔等额退款凭证。
- 创建及变更使用订单行锁，与系统退款 / 分账登记互斥。操作要求当前 revision，重复点击 / 旧页面操作不能越过状态校验。
- 非驳回人工记录（含结案）阻断本单新的系统自动退款和自动分账；不会因结案而重新开放自动资金操作。已发出的渠道请求不能撤回，仍允许查询原流水核实终态。
- 原订单、原支付单、渠道分账记录、收入流水不因人工结案被修改。查询原渠道已发出的交易仍按原核验逻辑记录结果，人工售后不等于撤销分账或冻结整个达人钱包。财务必须另外完成必要的追偿 / 账务核对，不能把凭证结案当作自动扣回达人款项。
- 凭证位置及内部处理记录仅在授权后台展示，用户 API 只返回是否需联系人工售后的能力标志。

## 验证

隔离数据库（不读 `.env`，不接业务库）：

```powershell
.\.venv\Scripts\python.exe scripts/check_wechat_auth.py backoffice.test_manual_refunds backoffice.test_staff_refunds backoffice.test_operations_queue backoffice.test_finance_work orders.test_distributions orders.test_distribution_safety orders.test_settlement_plans
```

后台：`npm run build`；`tests/manualRefunds.browser.cjs` 和 `tests/staffRefunds.browser.cjs` 全量模拟 API 并禁止外部访问。浏览器测试使用 `ADMIN_TEST_URL`、`PLAYWRIGHT_MODULE` 和可选 `CHROME_EXECUTABLE` 配置。

离线回归覆盖金额、幂等、权限与城市范围、状态版本、双人复核、凭证重复、自动流程拦截、待办及列表分页。SpatiaLite 回归不能替代 PostgreSQL 的真实并发锁验证，也未进行真实汇付退款或人工打款。

本期按汇付支付集成技能的既有系统改造、交易操作 FAQ 和上线检查指引执行：终态以原渠道证据为准，人工记录与渠道退款保持独立。官方接口证据尚不充分，因此不实现自动分账退回及余额 / 组合支付渠道结算。
